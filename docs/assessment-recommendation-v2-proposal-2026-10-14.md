# 精准职达：测评与岗位推荐 V2 设计方案

日期：2026-10-14。状态：供产品确认与开发评审的方案，未修改运行代码、题库、数据库或现有排序。

## 1. 本轮建议

保留已确认的前端旅程：上传/填写简历 → 性格与职业偏好测评 → 查看测评结果 → 主动继续岗位推荐 → 岗位库详情。从第三步回看测评仍使用弹窗，不跳回答题。

新版采用 **36 道原创探索题：18 道职业兴趣、12 道工作方式、6 道工作价值**。不再用人格分数推导霍兰德代码，不再输出“某种人格天生适合央国企/互联网”。兴趣参与规则推荐；工作方式与价值先用于解释、待确认提醒。保留行业/类别偏好与类别排除功能。

这是产品试用版设计，不是已验证的心理量表。36 题和各阈值是待试用调整的工程选择。答题时间先记录实测，再决定页面时长文案。

框架参考：[O*NET Interest Profiler](https://www.onetcenter.org/IP.html) 将职业兴趣分为 R/I/A/S/E/C 六类；其官方版本包括30题与60题。[Mini-IP 开发说明](https://www.onetcenter.org/reports/Mini-IP.html) 介绍了官方30题版本的开发工作。本方案的18道兴趣题是重新编写的产品题，不复制官方题目，也不继承官方量表的效度结论。以后若选择接入或改编完整量表，需要另行确认适用语言、许可与验证。

## 2. 当前实现审查

现有40题全部标注O/C/E/A/N五个人格维度；计分把结果映射到40–100；未提供答案时 helper 以3代入（正式提交虽检查完整，导入与其他调用仍需统一约束）。霍兰德代码由少量人格阈值分支生成；强肯定的“核心竞争优势”来自固定模板。现有推荐规则没有读取测评，职业资料有职责/技能/人格标签，但没有结构化、可核验的兴趣和环境画像。

不能把旧40题的分数改名为独立兴趣结果，也不能将保存成功、页面顺序正确视为双维推荐已成立。

## 3. 题目、选项与计分

答题提示：按目前真实感受作答，没有标准答案；没有做过不等于不喜欢。确实无法判断时选“暂时无法判断”，不自动按中间分处理。

兴趣题选项：1很不想做、2不太想做、3一般、4比较想做、5很想做、null暂时无法判断。只问想不想做，不问擅不擅长。

| ID | 指标 | 题目 | 方向 |

| W3 | 计划推进P | 面对较大的任务，我会先拆成几个可以完成的小任务。 | 正 |

| W8 | 分工明确G | 任务要求发生变化时，我希望先确认调整后的目标。 | 正 |

这些指标不叫“大五人格”。两端都描述工作方式，没有通用的“越高越优秀”；W11不是能力不足，低分不推出不适合服务、管理或销售。

### C. 工作价值（6题）

选项：1不重要、2不太重要、3一般、4比较重要、5很重要、null暂时无法判断。

| ID | 关注项 | 题目 |
| --- | --- | --- |
| V1 | 成就 | 对我来说，工作成果能被看见和认可很重要。 |
| V2 | 自主 | 对我来说，能自己决定部分工作方法很重要。 |
| V3 | 稳定 | 对我来说，工作安排和发展预期相对明确很重要。 |
| V4 | 支持 | 对我来说，遇到困难时能获得同事或导师支持很重要。 |
| V5 | 成长 | 对我来说，工作能持续带来新的学习机会很重要。 |
| V6 | 平衡 | 对我来说，工作之外有可安排的个人时间很重要。 |

每项仅一道题，作为用户直接表达的偏好，不宣称量表维度或精确心理得分。若多项均为4/5，结果确认页允许选最多两项“当前更优先”，也允许不选；这是可选确认操作，不增加必答题数。不把收入纳入人格判断，收入期望继续使用现有独立偏好字段。

### 计分与边界

1. R/I/A/S/E/C、P/X/G/T各三题。先对反向题执行6-x，再对非null答案取均值。每个指标至少两道有效答案才生成该指标，否则返回unknown并注明已答题数。
2. 展示均值1–5或“倾向不明显/偏好较明确”描述；图形内部可用(mean-1)/4×100，不称百分位、全国排名或胜任率。不沿用40分保底。
3. 兴趣优势取最高两类，但差值小于0.5时不强行排序；最高均值不足3.5，或最高最低差小于0.5，显示“兴趣暂未呈现明显倾向”。阈值是初版展示规则，需试用调整。
4. 价值展示原始选择与用户确认的优先项，不合成总人格分。
5. 全选3/全选5不会被判定无效或强制重测。兴趣均匀时不生成伪精确优势。答题过快仅非阻断提醒；初始阈值为超过一半题目停留少于1秒，计时需排除恢复草稿和后台切换，且不影响分数。
6. 提交需要36题均有合法答案或明确null。null与漏答不同，不能默认补3。未知ID、重复ID、错版本、范围外数值、前端自报分数均拒绝。服务器计分为准。

## 4. 用户看到什么

结果页顶部“测评结果”，依次展示：
- 你更感兴趣的工作活动：六类兴趣图，以及具体题目依据。例如“你对查资料、分析问题表现出较明确兴趣”。
- 你偏好的工作方式：计划推进、探索变化、分工明确、交流参与四项，以中性文字解释。
- 你当前看重什么：重要项与已确认优先项。
- 哪些还不确定：无法判断的指标及可补充的真实经历，不把低分解释成缺陷。
- “继续查看岗位推荐”。第三步弹窗回看以上同一份保存结果，重新答题走独立“重新测评”入口。

删除固定“卓越/天生适合/核心竞争优势”评语。结果不用AI实时生成，以透明模板和实际答案解释；AI可在后续目标岗位诊断里补充建议，但不能改分或创造证据。

## 6. 推荐规则：简历与兴趣共同作用

### 6.1 输出三类线索，而非单一“适合/不适合”

- **已有依据的方向**：材料中至少有一项核心技能关联，且有一条具体经历/成果线索。说明这些只是用户提供的材料，未验证熟练程度。
- **需要补证据的方向**：有技能/专业线索，但缺少经历依据。
- **兴趣探索方向**：兴趣较明确，但材料尚缺能力证据；不能显示“高匹配、推荐投递”。

推荐最多10条：先取前两类中最多7条，再取最多3条兴趣探索候选，去重；不足时只展示实际条数，不用无关类型补满。兴趣探索需用户存在明确兴趣、I≥.65，且该明确兴趣在职业画像中的权重≥.35（均为待校准的工程阈值）；否则探索区可以为空。名称不同但实际同义的职业应按人工维护的canonicalRoleId去重，避免“财务专员/财务会计岗”占据多个名额。

### 6.2 内部排序值（初版工程规则，待校准）

对有已审核兴趣映射、且用户兴趣完整的候选，使用：

`rank = .70 × C + .25 × I + .05 × P`

- C：材料证据覆盖，0–1。核心技能占.70、关联经历占.20、专业文字关联占.10。技能按经审核的and/or条件匹配，不让同一“Python”自动代表整条复合要求全部具备；经历须指出实际提供的项目/实习/成果原文，不仅“有项目就加满分”。没有资料记为unknown，并单独报告信息覆盖度；数值0仅表示“暂无关联证据”，不声称能力为0。不按缺失信息重新归一化，以免只有专业信息的材料得到满分。
- I：`Σ interestWeights[d] × (userMean[d]-1)/4`。联合计分的严格首版要求六个兴趣指标均可计算；有unknown时不补均值，降为明确标注的材料探索路径。平坦兴趣向量只带来相同或接近的兴趣贡献，不展示兴趣优势。
- P：行业命中.60、类别命中.40，未选择记0。类别排除是独立候选过滤。城市/收入尚无对应核验资料，继续只保存。

70/25/5是工程试验参数，不是心理学权重，不继承原PRD的“性格30%”。它用于同一证据类别内排序；先按上述证据类别分组，再比较rank。同分依次按C、I、catalogId稳定排序。学历仅提示参考要求，不作企业硬性资格过滤。

工作方式和价值 **首版不进rank**。有职业环境依据时，输出偏好相关的提醒及应向招聘方确认的问题；没有依据时说明待确认。这保证兴趣真正影响排序，同时不把未知的加班、稳定或外向要求填成事实。

### 6.3 推荐解释示例

数据分析师：
- 简历依据：“你提供了Python、SQL，并描述了处理课程问卷数据的经历。”
- 兴趣依据：“你对比较数据与解释问题的活动选择了比较想做/很想做。”
- 待补证据：“尚未看到复杂业务分析的案例，这不代表你不具备。”
- 工作方式提醒：“你希望分工明确；实际团队职责与支持方式需要进一步确认。”

不输出“性格匹配95%”“录用概率80%”或“你天生适合”。需要展示排序解释时，显示关联活动和材料，不向用户暴露rank为科学适配分。

## 7. 数据、接口与兼容

Assessment新增 `schemaVersion`、`questionnaireVersion`、`scoringVersion`、`profile Json?`、`qualityFlags Json?`。旧记录标为legacy-v1，保留既有字段和内容；V2 profile保存interest/workStyle/value及各指标有效答案数。旧字段不要填造新版霍兰德代码或假雷达结果；迁移时允许V2不再依赖旧必填展示字段，更新相关mapper/types。

新增或调整接口：
- GET `/api/assessment/questions?version=assessment-v2.0`：返回稳定ID、选项及版本。
- POST `/api/assessments`：新增版本化answers载荷；旧scores载荷仅在明确legacy-v1兼容路径处理。版本未知不猜。
- GET `/api/assessments/latest`：返回版本与对应结果，前端按版本展示。
- GET `/api/recommendations`：读取本人最新确认简历、有效测评、偏好和画像版本；不能信任客户端传入的用户ID或算好的分数。缺材料返回可操作409。
- 游客使用同一纯计分/排序模块；登录导入只接收版本与答案，服务器复算结果，**不能直接信任游客personalityResult/profile**。现有导入绕过完整答案复算的问题要在实现时一并修复。

旧40题结果继续可看，不自动当V2使用；旧用户选择“查看推荐”时可看清楚标记的材料探索结果，并提示新版测评能补充独立兴趣信息。不强制丢弃旧结果或重答才能访问岗位库。

草稿键改为 `assessment_draft:{userId}:{questionnaireVersion}`，旧草稿保留在旧版本，不把1–40答案套进新题ID。保存完整答案/版本，恢复时重新验证。“已经回答”按键是否存在判断，不能用`!answers[id]`把明确null当成漏答。更新到V2时让用户明确选择重新开始；未完成新版不能覆盖旧完整结果。

推荐记录建议增加 `RecommendationSnapshot`：owner、resumeId、assessmentId、各版本、preferencesHash、catalogProfileHash、输入hash、输出JSON、createdAt。重算键包括简历、测评、偏好、题库/计分/排序、职业画像版本；任一变化失效。历史记录保留当时快照，默认“当前推荐”使用最新有效输入。

登录和游客预览只允许服务端/本机存储各自身份的材料；慢响应不能覆盖新账号。删除测评/简历时同时清除当前推荐与对应缓存；历史隐私删除不能仅删除外键而保留个人解释JSON。分享仍只公开职业资料，未授权开放个人测评与报告。

## 8. 可复现验收案例

下表为待实现的合成测试，不是本轮已运行的产品效果验证。

| 场景 | 输入/变化 | 预期 |
| --- | --- | --- |
| 单调性 | 同一C=.80、P=0；I从.20变.80 | rank从.61变.76；同证据组内上升 |
| 兴趣区分 | 同简历、不同R/I/A兴趣；至少两个同证据组候选 | 有明确兴趣差异的候选顺序变化，并能追溯题目 |
| 能力/兴趣冲突 | 有分析项目，创意兴趣强，缺设计案例 | 设计出现在兴趣探索区，不冒充已有能力推荐 |
| 未知兴趣 | I维度只有1题有效 | 不补3分，不产生伪联合分；显示需补信息/材料探索 |
| 全选中间 | 六个兴趣均值3 | 不生成前三名伪优势，排名主要由材料区分 |
| 全选最低 | 六个兴趣均值1 | 不判人格差或强制重测；兴趣贡献为0 |
| 反向题 | W2答1、W1/W3答5 | P均值5；W2答5则反向分1 |
| 行业刻板印象 | 技能/活动画像相同，仅行业变央国企/互联网 | 人格、工作方式不额外改变排名；只有用户明示行业偏好可影响P |
| 空环境资料 | 缺稳定性/加班依据 | 只提出待确认问题，不生成适配百分比 |
| 草稿跨版 | V1第20题退出后打开V2 | 不套题、不丢旧草稿；V2从新题开始 |
| 导入篡改 | 客户端伪造profile/分数/他人ID | 服务端按本人会话与合法答案复算，不接受伪造结果 |
| 缓存变更 | 仅重新测评或调整偏好 | 当前推荐更新；旧报告仍有版本标签 |
| 体验连贯 | 完成→结果→推荐→回看弹窗→关闭 | 先看到结果；弹窗不重答、不丢推荐状态 |
| 容错隐私 | 保存失败/账号切换/删除资料 | 答案可重试，旧响应不串账号，个人缓存随删除清理 |
| 覆盖不足 | 意向职业尚无审核画像 | 明确材料探索与岗位库入口，不伪装联合覆盖346类 |

每项需有确定性规则测试；保存、版本、导入、缓存与账号隔离需真实专用数据库测试；完整旅程需浏览器验收。真实AI诊断单独授权与验收，不作为规则测试前提。

## 9. 开发批次与产品试用

1. 冻结题目/计分与版本结构，建立36题样例及上述测试向量。
2. 建立首批24个职业活动画像，逐条审核技能条件及兴趣依据。若这一步没有完成，不启用联合排序。
3. 实现服务端计分、旧版本读取、游客导入复算与版本草稿，接入既有结果页/回看弹窗。页面布局保持。
4. 实现联合推荐、分区解释、快照与失效/隐私清理，再接前端。完成后才能移除“测评未参与排序”说明。
5. 用5–8位目标用户试用，记录实际耗时、难理解题目、无法判断率与推荐理由是否符合真实材料；这只是初期可用性探索，不能证明心理测量有效性或总体满意度。
6. 扩展画像、校准参数；若正式需要专业测评定位，再决定采用经过验证的完整工具及本地化验证。

发布前检查：36题每题单一意思、选项含明确未知；反向题与版本无歧义；结果不夸大；每条排名可追溯材料与已审核映射；新增排序可回退；旧用户资料不丢；不同输入确有合理差异。付费、实时招聘采集、模拟面试与大规模运营后台不纳入这轮实现。
