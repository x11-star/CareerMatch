# 精准职达 CareerMatch

面向高校学生的职业类型诊断工具：上传并确认简历 → 完成工作偏好测评 → 选择职业类型 → 查看个人诊断与准备建议。

**本机继续开发先读 [START-HERE.md](START-HERE.md)。** 当前分支为 `careermatch-flow-completion`，以 1542418 为基线。

## 数据与功能边界

- 当前目录包含 346 个职业类型，资料来自历史表格与模型整理，不是实时招聘信息。
- 不绑定企业、招聘城市或福利。薪资、难度、招聘节奏与技能要求仅供职业探索，具体要求以招聘公告为准。
- 职业库可按行业、类别和关键词主动浏览；职业推荐页依据材料及行业/类别偏好排序，最多展示 10 个有相关线索的职业，逐条说明理由、证据差距和未知信息。不代表录用概率。
- 前端入口：上传/手动填写材料 → 性格测评 → 推荐方向 → 岗位库详情。顶栏只保留首页、岗位库、我的档案；首页与档案承接继续流程和查看推荐。
- 当前推荐后端仍按简历与偏好排序，测评暂未参与排名，页面明确披露。双维推荐与量表重构是下一阶段，不能将流程调整当成推荐算法已经升级。
- 学历、语言、证书与经历成果可补充并保存。缺失信息按未知处理；类型学历要求只作提醒，不作为企业招聘资格判定。
- 城市、收入与工作价值偏好保存但不参与本轮排序，职业类别排除项会移出候选。
- 个人诊断由真实配置的智谱/DeepSeek 服务生成。没有密钥或服务失败时明确报错，不用默认简历或随机分数替代。
- 自编测评沿用大五维度与规则推断的兴趣标签，得分是内部量表结果，不是全国常模、科学百分位或录用概率。
- 证据区的技能对照为关键词检查，软技能待验证；7 天/30 天行动建议为通用准备清单，不能冒充个性化 AI 建议。
- 分享链接只公开职业资料，不携带个人简历、测评或诊断。

## 技术栈

React 19、TypeScript、Vite、Tailwind v4、motion/react；Node.js/Express；PostgreSQL/Prisma；智谱优先、DeepSeek 兜底；mammoth/pdf-parse/pdfjs-dist/canvas 与本地 Tesseract OCR；Playwright Chromium 生成 PDF。

Firebase 已退出应用运行路径，历史配置文件仅作迁移参考。

## 在其他电脑初始化

1. 安装 Node.js（建议当前受支持的 LTS）与 PostgreSQL，创建独立开发库和测试库。
2. `npm ci` 安装锁定依赖。若环境限制安装脚本，按包管理器提示允许 Prisma、canvas 和 esbuild 所需脚本；随后运行 `npm run db:generate`。
3. 复制 `.env.example` 为 `.env`，填写开发数据库连接、专用测试库连接以及 AI 密钥。**测试库不能与开发库相同。**
4. 执行 `npm run db:migrate`、`npm run db:seed`。
5. 执行 `npx playwright install chromium` 预先安装 PDF 所需浏览器。`chromium.launch()` 不会在首次导出时自动下载。
6. `npm run dev` 启动，默认 http://localhost:3000 ，可用 `PORT` 修改。

当前电脑的便捷启动脚本使用独立端口 4317 与便携式数据库 55437，详见 START-HERE。

## 认证与存储

- 登录使用开发手机号验证码，默认 `123456`；不发送真实短信。这是本地开发功能，不能直接作为生产认证方案。
- 服务端使用 HttpOnly Cookie `careermatch_session`，默认 7 天；前端不保存会话令牌。
- 登录材料由后端按会话用户读写 PostgreSQL。切换身份时重建资料区，旧请求不能写回新身份。
- 游客简历、完整测评、求职偏好、资料与收藏存 localStorage；测评答题草稿存当前标签页的 sessionStorage，并按身份区分。两者均为产品明确披露的本机体验策略。
- 登录后检测到游客材料时询问是否同步；失败会提示且保留原材料，不冒充成功。
- 我的档案可删除全部简历或测评记录与关联诊断；游客可清除全部资料并退出；账号注销需验证码。
- 上传的文字会发送给已配置的 AI 服务，前端不持有 Provider 密钥。请勿上传你无权处理的材料。

## 文件与诊断

支持 TXT、DOCX、文本 PDF、JPG/PNG/WebP、扫描 PDF；单文件 8MB；扫描 PDF 默认最多处理前 3 页，送入 AI 的文本有长度上限。本地 OCR 首次可能需要下载语言数据，效果需要用实际中文样例验收。

保存失败时保留材料/答案并提供重试，不进入下一步。服务端复算完整测评答案，过滤前端附加字段后保存简历。

登录用户的诊断缓存包含简历、测评及职业内容版本；更新材料后不能复用旧诊断。详情与职业库的收藏实际读写；个人档案显示已存收藏。

## PDF 导出

`POST /api/reports/export`，要求已登录、保存简历、完成测评且已经生成对应职业诊断。服务端读取本人材料与匹配缓存，使用真实 Chromium 生成自包含 A4 PDF。

缺少材料返回可操作的 409；未登录返回 401；渲染失败返回错误。前端检查 PDF 响应类型后才触发下载。中文字体需要在运行环境可用，Windows 验证不等于 Linux 部署字体验收。

## 测试

| 命令 | 覆盖 |
|---|---|
| `npm run typecheck` | TypeScript 检查，包括 React 类型 |
| `npm run build` | 前端与服务器打包 |
| `npm run test:ai` | 输出结构、兜底与 Provider 测试替身 |
| `npm run test:files` | 文件限制、解析与 OCR 模块逻辑 |
| `npm run test:data` | 目录字段、规则推荐、不同材料区分、排除项与未知信息边界 |
| `npm run test:frontend` | 工具函数、文案、链接与草稿恢复 |
| `npm run test:reports` | 报告数据、HTML 与替身渲染服务 |
| `npm run test:db` / `test:auth` / `test:api` | 专用 PostgreSQL 集成；会清理测试表 |
| `npm run test:e2e` | 旧流程与职业推荐浏览器集成，旧流程 AI 为测试夹具，新推荐不调用 AI，PDF 为真实 Chromium |
| `npm run test:e2e:recommendations` | 仅手动填写、偏好保存、推荐、游客同步、隔离与响应式 |

测试脚本在未配置 `TEST_DATABASE_URL` 时会跳过数据库组，退出码 0 不能算通过。真实 Provider 与真实图片/扫描 PDF OCR 必须独立报告。
